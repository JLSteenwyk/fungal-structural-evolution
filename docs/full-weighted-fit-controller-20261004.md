## Resource limits and preserved attempts

Each fitting producer/reader receives two CPUs, 32 GiB RAM, zero cgroup swap
and one OpenBLAS/OMP/MKL thread. Native children additionally receive 24-GiB
address-space, 2-GiB per-file and separately admitted CPU limits. Minimum
available host RAM is 64 GiB and free disk 3,172 GiB, with the existing 3-TiB
output/scratch allowance. GPU prediction remains paused; no paid resource
is provisioned. CPU capacity uses four times conditional point costs plus
604,800 seconds per role for uncalibrated source/export/review work. It is
**not an ETA, runtime bound or convergence guarantee**. No production
wall-time timeout is added.

Runtime checks actual cgroup limits, swap/OOM counters, BLAS environment and
native command. Exclusive role directories preserve configuration, wrapper
PID/create/command/invocation, native PID/create/command, stdout/stderr and
terminal receipt. Completed and failed attempts cannot automatically restart.
Cumulative child RSS is labeled explicitly, not an isolated per-child or
cgroup peak. Unexpected validation failures retain existing attempt files.

Closure requires successful original role receipts, exact commands/limits,
consistent process/configuration identities, complete log/artifact sets,
source bindings and native output hashes. It binds the full producer/reader
summaries, all original candidate/link output, completed readback marker and
two original dependency-controller journals through the existing full hash-
archive closer. Successful production launch, native fitting, independent
numerical/link readback and actual closure remain **unexecuted and unproven**.
The following software evidence covers its specified boundaries only.
