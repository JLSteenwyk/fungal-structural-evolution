# Recovery after the September 25 host reboot

The host had approximately eight minutes uptime at the first recovery check.
All four previously monitored project process handles were missing, and no
fungal transient user services remained loaded. This was confirmed termination,
not an observation timeout. An unrelated IQ-TREE process was left untouched.

Three CPU services were restored with new boot-bound recovery plans, preserving
the original plans and outputs:

- Species PMSF: `metadata/recovery_20260925_pmsf_plan.json`, 16 CPU equivalents,
  650 GiB memory limit. The checkpoint was hashed and copied before recovery;
  the native log confirms restoration of site frequencies, the initial tree,
  and 1,000 bootstrap trees. This does not mean inference is complete.
- ESMFold-based paired fits: `metadata/recovery_20260925_paired_fit_plan.json`,
  four CPU equivalents, 16 GiB memory limit; 228 existing fit receipts.
- AlphaFold-based paired fits:
  `metadata/recovery_20260925_afdb_paired_fit_plan.json`, four CPU equivalents,
  16 GiB memory limit; 120 existing fit receipts.

Commands, process identities, and boot ID are recorded in
`metadata/recovery_20260925_core_launches.json`. All three services were verified
live with native child processes. Original dependency pins are checked by the
recovery wrappers. Runtime remaining is uncalibrated. No paid resources or GPU
predictions were started.

The geometry log contains 101 processed markers, but inspection of
`prepare_paired_site_geometry.py` showed that results were accumulated in memory
until the entire cohort finished. The final output directory does not exist.
Those log entries therefore do not constitute recoverable geometry outputs.
Geometry requires checkpointing before recomputation. Its dependent controllers,
the other queued analyses, and retrieval still require recovery review; they
must not be described as running based on their pre-reboot state files.
