# Recovery following the September 16 reboot

The September 15 pause completed: 32 recorded project processes were suspended,
and a transient user timer was armed for September 16 at 00:05 Pacific local
time (PDT), 03:05 Eastern. That timer did not produce a recorded successful
resume. At the next inspection, the host reported a reboot at September 16
08:58:50 Eastern; none of the original process identities survived and the
transient timer was absent. The available evidence does not establish the
precise reason the scheduled continuation did not occur before the reboot.
Suspended process memory is not preserved across a reboot.

Eight reviewed restartable jobs were relaunched using their original commands:
longer ESMFold predictions, marker gene trees, alternative-copy trees,
taxon-identity sensitivities, both FCS guide trees, full Pfam searches and
AlphaFold retrieval. Completed outputs are checked by the existing runners.
The ESMFold directory contained 2,477 prediction receipts at recovery; startup
validates cached artifacts before proceeding. IQ-TREE guide logs explicitly
report restoring model parameters and candidate trees from checkpoints.

Four domain tables without completion receipts (chunks 052–055) were moved,
with recorded hashes, into results/recovery-20260916/incomplete-domain-tables.
Completed tables remain in place; these four incomplete searches are rerun.

The first supported PMSF run had only logs and its frozen guide/configuration;
there was no checkpoint, completed tree or saved profile file. All original
pinned inputs and executable hashes were checked. Its logs are retained and
the same analysis was relaunched in pmsf-profile-profile-recovery-v2. This is
recomputation, not restoration of the lost in-memory optimization. The original
resource plan remains applicable: one concurrent 16-thread PMSF process,
600-GB IQ-TREE memory ceiling and a 750-GiB available-memory launch gate.

Recovered jobs share the same 24-core CPU allowance. ESMFold continues with
30-second run/rest periods; the saved approximately 24-hour remaining cooling
duration resumes with the work. The live controller state is now
results/recovery-20260916/cooling_v2_state.json, with configuration in
metadata/recovery_20260916_cooling_v2_config.json. The earlier cooling recovery
controller was stopped cleanly before this replacement was launched.

Outstanding recovery work: OrthoFinder's partial alignments and gene trees,
including pre-existing FAMSA errors, need per-family review before continuation.
Prediction-completion and crossed-PMSF controllers need replacement parent
identities and output references. Do not reuse the dead pre-reboot PID records.
No DGX Spark jobs are active or requested.

Provenance: metadata/project_pause_20260915_*,
metadata/recovery_20260916_*, results/recovery-20260916/launch.json and its
per-job logs. Recovery launcher: scripts/recover_checkpointed_jobs_20260916.py.
This one-time launcher refuses duplicate invocation after its launch record
exists. It does not provide a general reboot recovery service.

## Completion controllers and OrthoFinder inventory

Replacement prediction snapshot and crossed-PMSF controllers are now attached
to the recovered producer identities, verified by PID/start time and command.
Their new control directories preserve previous attempts. The prediction
controller still requires a clean full 5,510-model completion receipt before
its artifact audit and conversion; the crossed controller still runs remaining
PMSF combinations serially after a verified first-run receipt. Dependency hashes
were rechecked when generating the replacement configurations.

Initial short-lived launcher attempts did not persist and created no controller
or audit output directories. They were replaced with tracked execution sessions;
actual live identities are in
metadata/recovery_20260916_completion_controller_launch.json. This distinguishes
launched-and-verified processes from intended commands.

An interrupted-family inventory is running over all 104,138 OrthoFinder source
FASTA files. The working directory also contains 43,715 alignment files and
32,638 tree files, including one empty tree. Input files total approximately
9.8 GB; the largest alignment is 1.577 GB and is streamed record by record.
One CPU core is assigned. Source-file hashes, duplicate IDs, alignment tip/width
checks, retained-residue subsequence checks, tree tip/branch checks and orphan
artifacts are recorded without modifying the originals. These checks do not
establish homology or reconstruct the exact trimming mask. Missing trees may
be normal for small families and require upstream-workflow interpretation.

The installed OrthoFinder 3.1.5 argument parser supports `--from-groups` and
`--from-trees`; the abbreviated help did not list those paths. No continuation
command has been run against the incomplete grid. The inventory and earlier
FAMSA failures must be reviewed before choosing a continuation strategy.
Script: scripts/audit_interrupted_orthology_families.py. Plan and live identity:
metadata/orthology_interrupted_family_inventory_{plan,launch}.json. Results:
results/orthology/interrupted-family-inventory-v1.
